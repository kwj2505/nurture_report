# 🌱 유치부 양육보고서 추출 (GAS 보안 버전)

## 왜 GitHub Pages가 아니라 Google Apps Script인가
기존 방식(정적 `index.html`을 GitHub Pages로 배포)은 소스 코드 안에 구글 시트 주소가 그대로 들어있어서,
**공개 저장소를 열어본 사람이 그 주소를 따라가면 예꼬들의 이름·생년월일·연락처·주소가 그대로 보이는 문제**가 있었다.

이 폴더의 `Code.gs` + `Index.html`은 그 문제를 없앤 버전이다.
- 실제 시트 조회는 전부 **서버(Apps Script)** 안에서 일어난다.
- 브라우저(클라이언트) 쪽 소스 어디에도 시트 주소가 없다 — `Code.gs`도 마찬가지(주소는 코드가 아니라 "스크립트 속성"에 저장).
- 그래서 이 두 파일은 **GitHub에 Public(공개) 저장소로 올려도 안전**하다.

## 배포 방법 (최초 1회)

### 1단계: Apps Script 프로젝트 만들기
1. drive.google.com 접속 → **새로 만들기 → 더보기 → Google Apps Script**
2. 프로젝트 이름을 "유치부 양육보고서 추출" 등으로 변경

### 2단계: 코드 붙여넣기
1. 기본 `Code.gs`의 내용을 전부 지우고, 이 폴더의 `Code.gs` 내용을 그대로 붙여넣기
2. 왼쪽 메뉴 `+` → **HTML** → 파일 이름을 정확히 `Index` (대문자 I)로 생성
3. 생성된 `Index.html`에 이 폴더의 `Index.html` 내용을 그대로 붙여넣기
4. `Ctrl+S`로 저장

### 3단계: 시트 주소 등록 (여기가 핵심 — 코드에 절대 직접 적지 않는다)
1. 왼쪽 톱니바퀴 아이콘 **"프로젝트 설정"** 클릭
2. 맨 아래 **"스크립트 속성"** 섹션 → **"스크립트 속성 추가"**
3. 아래 2개를 추가:

   | 속성(키) | 값 |
   | :--- | :--- |
   | `SHEET1_LINK` | 1부 예꼬 주소록 시트 링크 (`https://docs.google.com/spreadsheets/d/.../edit?gid=...`) |
   | `SHEET2_LINK` | 2부 예꼬 주소록 시트 링크 |

4. 저장

   > `ALLOWED_EMAILS`라는 속성도 코드에 준비돼 있지만 **양육팀 교사 전원의 이메일을 일일이 등록하기 어려운 경우엔 생략**하면 된다. 그러면 5단계의 "링크를 아는 사람만 접근" 방식으로만 제한된다(아래 참조). 나중에 특정 계정을 완전히 차단하고 싶을 때만 추가로 등록하면 된다.

### 4단계: 권한 승인 + 점검
1. 함수 선택 박스에서 `checkSetup`을 선택하고 ▶ 실행
2. "승인 필요" 창이 뜨면: 권한 검토 → 본인 계정 선택 → 고급 → 이동(안전하지 않음) → 허용
3. 하단 "실행 로그"에 두 시트 속성이 `✅ ... 설정됨, 시트 열기 성공`으로 뜨면 준비 완료(`ALLOWED_EMAILS`는 생략했다면 `⚠️ 미설정` 로그가 뜨는데, 의도한 상태이니 무시해도 된다)

### 5단계: 웹 앱으로 배포 (실행 주체 / 액세스 권한이 가장 중요)
1. 오른쪽 위 파란 **"배포" → "새 배포"**
2. 유형(톱니바퀴) → **웹 앱**
3. **실행 주체: 반드시 "나(Me)"** — "요청 사용자"로 하면 안 됨. "나"로 해야 접속하는 사람이 시트에 직접 권한이 없어도 데이터를 받아볼 수 있다(시트를 비공개로 유지하는 핵심 이유).
4. **액세스 권한: "모든 Google 계정 사용자"(추천)** — 이 배포 URL(`.../exec`)은 무작위 긴 문자열이라 링크를 모르면 접근할 수 없다. "모든 Google 계정 사용자"로 하면 **누구에게 이메일을 등록할 필요 없이, 이 링크를 받은 사람만** 접근할 수 있고(구글 로그인은 필요) 아이들 개인정보라 완전 익명 접근("모든 사용자")보다는 이쪽을 권장한다.
5. **배포** 클릭 → 생성된 URL(`https://script.google.com/macros/s/.../exec`)이 실제 서비스 주소 — 이 링크를 양육팀 교사분들께 전달하면 됨

### 6단계: 구글 사이트 도구 버튼에 연결
기존 "양육보고서 추출(개발중)" 버튼의 링크를 5단계에서 만든 URL로 교체하면 끝.

## 7단계: 교사 업로드 기능 설정 (2026-09-02 추가, 선택 사항)

각 반 교사가 엑셀을 받아서 뒷부분(특별사항 등)만 수정해 다시 올리면, "양육시트 합본"이라는 **별도의 새 구글시트**에 자동으로 모이는 기능이다. 원본 마스터 시트(1부/2부 예꼬 주소록)에는 절대 쓰지 않는다.

1. (선택) 합본 시트를 특정 드라이브 폴더 안에 만들고 싶으면, 프로젝트 설정 → 스크립트 속성에 `MERGED_FOLDER_LINK` = 그 폴더 링크(`https://drive.google.com/drive/folders/...`) 등록. 생략하면 "내 드라이브" 최상위에 생성됨(나중에 수동으로 옮겨도 URL은 안 바뀜).
2. 함수 선택 박스에서 `setupMergedSheet`를 선택하고 ▶ 실행 (SHEET1_LINK/SHEET2_LINK가 먼저 설정돼 있어야 함)
3. 실행 로그에 뜨는 **합본 시트 URL**을 복사
4. 프로젝트 설정 → 스크립트 속성에 `MERGED_SHEET_LINK` = 그 URL 등록
5. 왼쪽 메뉴 **"서비스" 옆 `+`** 클릭 → **Drive API** 추가(업로드된 엑셀을 읽으려면 필요)
6. (선택) 업로드를 교사 계정만 되게 좁히고 싶으면 스크립트 속성에 `TEACHER_EMAILS`(쉼표 구분 이메일) 추가. 생략하면 조회 가능한 사람 누구나 업로드도 가능.
7. `checkSetup` 다시 실행해서 `TEACHER_EMAILS`/`MERGED_SHEET_LINK`/`MERGED_FOLDER_LINK` 상태 확인

**업로드 화면은 `TEACHER_EMAILS`에 등록된 계정으로 접속했을 때만 보인다.** 같은 반을 다시 올리면 이전 내용을 자동으로 덮어쓰고(중복 없음), 화면에서 고른 반과 파일 내용이 다르면 업로드 자체가 거부된다. 다운로드되는 엑셀은 이름·반·학년 등 식별 열이 잠겨있어(실수 방지용) 뒷부분 서술형 열만 수정할 수 있다.

> ⚠ `Drive.Files.insert`가 "함수가 아닙니다" 오류를 내면, 추가한 Drive API 고급 서비스가 v3 버전이라 그런 것이다. `Code.gs`의 `convertXlsxToTempSheet_` 함수 안 주석에 v3용 코드가 적혀있으니 그걸로 바꾸면 된다.

## 매년(예: 12월) 시트 주소가 바뀔 때 — 코드 수정 없이 딱 여기만

1. Apps Script 편집기 → 왼쪽 톱니바퀴 **"프로젝트 설정"**
2. **"스크립트 속성"**에서 `SHEET1_LINK` / `SHEET2_LINK` 값을 새 주소로 수정 → 저장
3. **끝.** 코드 수정도, 재배포도 필요 없다 — 다음 요청부터 바로 새 주소로 조회된다.
4. (합본 시트를 매년 새로 시작하고 싶으면) `MERGED_SHEET_LINK` 속성을 지우고 `setupMergedSheet` 다시 실행 → 새 URL로 속성 갱신

## 파일 구성
- `Code.gs` — 서버: 시트 조회(읽기 전용) + 교사 업로드 처리(합본 시트에만 씀), 스크립트 속성에서 설정값 로딩, `doGet`으로 화면 서빙
- `Index.html` — 클라이언트: 부서/학년/반 선택 UI, 카드형 결과, 텍스트복사/엑셀다운로드(식별 열 잠금)/이미지저장, 교사 업로드 카드 (디자인은 01~04번 도구와 동일)
- 원본 마스터 시트(1부/2부 예꼬 주소록)에 쓰는 코드는 어디에도 없음 — 완전 읽기 전용. 쓰기는 오직 별도의 "합본" 시트에만 일어남.
